The second preview of ReGa: a Linux desktop app that runs a Windows gaming
machine in your own AWS account, sets it up, and streams it to your desktop
with Moonlight. You now sign in to AWS in the app itself, and the Flatpak is
built from source.

## Install

On Ubuntu, or any x86_64 Linux with Flatpak:

```sh
sudo apt install flatpak
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
wget -O rega-x86_64.flatpak https://github.com/sergimn/ReGa/releases/download/v0.0.2/rega-x86_64.flatpak
wget -O SHA256SUMS https://github.com/sergimn/ReGa/releases/download/v0.0.2/SHA256SUMS
sha256sum -c SHA256SUMS && flatpak install --user rega-x86_64.flatpak
flatpak install --user flathub com.moonlight_stream.Moonlight   # to play
flatpak run io.github.sergimn.rega
```

Installing also pulls the `org.freedesktop.Platform` 25.08 runtime from
Flathub. If Flatpak is new on your computer, ReGa and Moonlight show up in
the app menu after you log out and back in.

To update from 0.0.1, install this bundle the same way; your machines and
their state stay where they are, in your AWS account. Uninstalling
(`flatpak uninstall --user io.github.sergimn.rega`) doesn't touch your AWS
account, so destroy the machines you no longer want in the app first. It
also leaves your saved access key in `~/.var/app/io.github.sergimn.rega`:
sign out in the app before you uninstall, or add `--delete-data` to remove
it with the rest of ReGa's data.

## Signing in has changed

ReGa now only uses the AWS credentials you enter in it. On the AWS page,
choose **Enter credentials** and type an IAM user's access key ID and secret
access key. ReGa checks them with AWS before keeping them, then says which
IAM user and account it's signed in as, so a wrong account shows. **Change
credentials** and **Sign out** are on the same page. Until you sign in, it
shows sample data, so you can look around first.

The key is kept in your system keyring: in the Flatpak, through the desktop's
Secret portal, which GNOME Keyring provides on Ubuntu. If it can't be saved
there, ReGa says so and stays signed in until you quit it.

ReGa no longer reads `~/.aws`, environment variables or any other credentials
it finds on the computer, and neither does the Terraform it runs. So, coming
from 0.0.1:

- Enter your access key in the app once on each computer you use ReGa on,
  even if `~/.aws` already has one.
- AWS SSO and other temporary credentials can't be entered; use an IAM
  user's long-term access key.
- The `AWS_PROFILE` override the 0.0.1 notes suggested does nothing now.
  `flatpak override --user --reset io.github.sergimn.rega` removes it, along
  with any other override you set for ReGa.

## Before you launch a machine

The AWS account needs:

- An IAM user for ReGa's access key, with this policy. It lets ReGa run
  machines and their idle alarms and create and use its two S3 buckets; its
  only IAM permission is to give its machines `ReGaInstanceRole`. Signing in
  only checks that the key is valid, so a missing permission shows up later,
  as an error when ReGa first needs it.

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "Read",
        "Effect": "Allow",
        "Action": [
          "sts:GetCallerIdentity", "ec2:Describe*", "ec2:GetPasswordData",
          "cloudwatch:DescribeAlarms", "cloudwatch:ListTagsForResource",
          "pricing:GetProducts", "servicequotas:GetServiceQuota"
        ],
        "Resource": "*"
      },
      {
        "Sid": "Machines",
        "Effect": "Allow",
        "Action": [
          "ec2:RunInstances", "ec2:StartInstances", "ec2:StopInstances",
          "ec2:TerminateInstances", "ec2:ModifyInstanceAttribute",
          "ec2:CancelSpotInstanceRequests", "ec2:CreateTags", "ec2:DeleteTags",
          "ec2:CreateVolume", "ec2:DeleteVolume", "ec2:AttachVolume",
          "ec2:DetachVolume", "ec2:CreateSecurityGroup",
          "ec2:DeleteSecurityGroup", "ec2:AuthorizeSecurityGroupIngress",
          "ec2:AuthorizeSecurityGroupEgress", "ec2:RevokeSecurityGroupIngress",
          "ec2:RevokeSecurityGroupEgress", "ec2:ImportKeyPair",
          "ec2:DeleteKeyPair", "cloudwatch:PutMetricAlarm",
          "cloudwatch:TagResource", "cloudwatch:DeleteAlarms"
        ],
        "Resource": "*"
      },
      {
        "Sid": "SetUpBuckets",
        "Effect": "Allow",
        "Action": [
          "s3:CreateBucket", "s3:GetBucketLocation",
          "s3:GetBucketPublicAccessBlock", "s3:GetBucketVersioning",
          "s3:PutBucketVersioning", "s3:GetEncryptionConfiguration",
          "s3:PutEncryptionConfiguration", "s3:GetBucketTagging",
          "s3:PutBucketTagging", "s3:GetLifecycleConfiguration",
          "s3:PutLifecycleConfiguration"
        ],
        "Resource": ["arn:aws:s3:::rega-tfstate-*", "arn:aws:s3:::rega-games-*"]
      },
      {
        "Sid": "UseBuckets",
        "Effect": "Allow",
        "Action": ["s3:ListBucket", "s3:GetObject", "s3:PutObject", "s3:DeleteObject"],
        "Resource": [
          "arn:aws:s3:::rega-tfstate-*", "arn:aws:s3:::rega-tfstate-*/*",
          "arn:aws:s3:::rega-games-*", "arn:aws:s3:::rega-games-*/*"
        ]
      },
      {
        "Sid": "GiveMachinesTheirRole",
        "Effect": "Allow",
        "Action": "iam:PassRole",
        "Resource": "arn:aws:iam::*:role/ReGaInstanceRole",
        "Condition": {
          "StringEquals": {
            "iam:PassedToService": "ec2.amazonaws.com"
          }
        }
      }
    ]
  }
  ```

- A GPU quota in the region you pick: "Running On-Demand G and VT instances"
  of at least 4 vCPUs for a g4dn.xlarge, and "All G and VT Spot Instance
  Requests" for spot. The app shows each region's quota.
- An IAM role for EC2 with an instance profile, both named
  `ReGaInstanceRole` (creating the role in the IAM console makes both). The
  machine uses it to read and write your game library and to fetch the
  NVIDIA driver, so give it this policy:

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "GameLibrary",
        "Effect": "Allow",
        "Action": ["s3:ListBucket", "s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:GetBucketLocation"],
        "Resource": ["arn:aws:s3:::rega-games-*", "arn:aws:s3:::rega-games-*/*"]
      },
      {
        "Sid": "NvidiaGamingDriver",
        "Effect": "Allow",
        "Action": ["s3:ListBucket", "s3:GetObject"],
        "Resource": ["arn:aws:s3:::nvidia-gaming", "arn:aws:s3:::nvidia-gaming/*"]
      }
    ]
  }
  ```

- Once per account, as an admin, the role CloudWatch needs to stop an idle
  machine: `aws iam create-service-linked-role --aws-service-name events.amazonaws.com`
  (and, before your first spot machine, the same with `spot.amazonaws.com`).

## What's new

- **Signing in.** You enter your AWS access key in ReGa, which keeps it in
  the system keyring (see above).
- **About and licences.** The info button at the bottom of the side menu
  opens About, with ReGa's version and licence. **View licenses** lists
  ReGa's licence first, then the notices the Flatpak ships: every Rust crate
  built into the app with its version and licence texts, the Rust standard
  library's notices, Terraform's licence and the AWS logo's trademark notice
  (the Flatpak keeps these in `/app/share/licenses/io.github.sergimn.rega/`),
  along with those of Flutter and the Dart packages.
- **The AWS logo** stands for the AWS platform in the side menu, in place of
  a generic cloud. It's a trademark of Amazon.com, Inc. or its affiliates;
  ReGa isn't affiliated with or endorsed by AWS.
- **Game library restore during setup.** When a machine is launched straight
  on a GPU type, the reboots of its first setup used to cut the restore of
  your games from S3 short. The restore now waits for the setup to finish
  (for up to two hours) before it starts.
- **Built from source.** flatpak-builder now compiles the app and its Rust
  core itself, the way Flathub builds apps: offline, with a Flutter SDK, a
  Rust toolchain and every crate and Dart package pinned by hash. Some parts
  still come prebuilt: Flutter's engine (Google's release build),
  Terraform, and five of the Python packages Ansible needs (the ones with
  compiled code).

## What it does

- Picks a region by latency and price, and shows the machine types with
  their specs and hourly price, on-demand or spot.
- Launches a Windows machine and installs Steam, Sunshine and a WireGuard
  server on it, optionally on a cheap CPU type first and then switched to
  the GPU. It copies your games from your S3 bucket to the machine's disk.
- Starts, stops, resizes and destroys machines, and saves your games back to
  S3 before a stop or a destroy. A machine stops itself after 15 minutes
  without a stream.
- Streams a running machine: its Play button opens ReGa's own WireGuard
  tunnel to it (no root, no system VPN) and pairs Moonlight with its
  Sunshine. From the Flatpak you pair by hand once per machine: add the
  host ReGa shows in Moonlight, type the PIN Moonlight shows into ReGa, then
  start Desktop in Moonlight. Keep ReGa open while you play, since the
  stream goes through it. With WireGuard turned off at launch, Moonlight
  goes straight to the machine's public IP instead, which changes at every
  start, so you add the host again after each one.
- Keeps each machine's state in your own S3 bucket, so every computer you
  run ReGa on sees the same machines, and lists any leftover resources with
  a button to delete them.

## Not there yet

- A full run on AWS. The Terraform has launched real (CPU) machines, and
  CI runs the setup playbook on a real Windows Server and reaches its
  Sunshine through ReGa's tunnel. But the app hasn't yet taken a machine
  from launch to a stream to a stop on AWS, and nothing has run on a real
  GPU machine.
- Keeping the key from inside the Flatpak. CI tests the keyring outside the
  sandbox, but the Flatpak's way through the Secret portal hasn't been tried
  on a real desktop yet. Desktops without a Secret portal can't keep the key,
  so you enter it again each time you start ReGa.
- The licence page doesn't list Ansible and the Python packages the Flatpak
  bundles for it yet.
- x86_64 only, and not on Flathub yet.
