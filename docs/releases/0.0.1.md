The first preview of ReGa: a Linux desktop app that runs a Windows gaming
machine in your own AWS account. This release launches and sets up the
machine; streaming it to your desktop comes in the next one.

## Install

On Ubuntu, or any x86_64 Linux with Flatpak:

```sh
sudo apt install flatpak
flatpak remote-add --user --if-not-exists flathub https://dl.flathub.org/repo/flathub.flatpakrepo
wget -O rega-x86_64.flatpak https://github.com/sergimn/ReGa/releases/download/v0.0.1/rega-x86_64.flatpak
wget -O SHA256SUMS https://github.com/sergimn/ReGa/releases/download/v0.0.1/SHA256SUMS
sha256sum -c SHA256SUMS                # checks the download
flatpak install --user rega-x86_64.flatpak
flatpak run io.github.sergimn.rega
```

Installing also pulls the `org.freedesktop.Platform` 25.08 runtime from
Flathub. If Flatpak is new on your computer, ReGa shows up in the app menu
after you log out and back in.

To update, install a newer bundle the same way. Uninstalling
(`flatpak uninstall --user io.github.sergimn.rega`) doesn't touch your AWS
account, so destroy the machines you no longer want in the app first.

## Before you launch a machine

ReGa reads your AWS credentials from `~/.aws`, using the `default` profile.
For another profile (an SSO one works too), run
`flatpak override --user --env=AWS_PROFILE=<name> io.github.sergimn.rega` once.
Without credentials it shows sample data, so you can look around first. To
launch a machine, the account also needs:

- A GPU quota in the region you pick: "Running On-Demand G and VT instances"
  of at least 4 vCPUs for a g4dn.xlarge, and "All G and VT Spot Instance
  Requests" for spot. The app shows each region's quota.
- An IAM role for EC2 with an instance profile, both named
  `ReGaInstanceRole` (creating the role in the IAM console makes both). The
  machine uses it to read and write your game library and to fetch the
  NVIDIA driver, so give it this policy:

  ```json
  {
    "Version": "2012-10-17",
    "Statement": [
      {
        "Sid": "GameLibrary",
        "Effect": "Allow",
        "Action": ["s3:ListBucket", "s3:GetObject", "s3:PutObject", "s3:DeleteObject", "s3:GetBucketLocation"],
        "Resource": ["arn:aws:s3:::rega-games-*", "arn:aws:s3:::rega-games-*/*"]
      },
      {
        "Sid": "NvidiaGamingDriver",
        "Effect": "Allow",
        "Action": ["s3:ListBucket", "s3:GetObject"],
        "Resource": ["arn:aws:s3:::nvidia-gaming", "arn:aws:s3:::nvidia-gaming/*"]
      }
    ]
  }
  ```

- Once per account, as an admin, the role CloudWatch needs to stop an idle
  machine: `aws iam create-service-linked-role --aws-service-name events.amazonaws.com`
  (and, before your first spot machine, the same with `spot.amazonaws.com`).

## What it does

- Picks a region by latency and price, and shows the machine types with
  their specs and hourly price, on-demand or spot.
- Launches a Windows machine and installs Steam, Sunshine and a WireGuard
  server on it, optionally on a cheap CPU type first and then switched to
  the GPU. It copies your games from your S3 bucket to the machine's disk.
- Starts, stops, resizes and destroys machines, and saves your games back to
  S3 before a stop or a destroy. A machine stops itself after 15 minutes
  without a stream.
- Keeps each machine's state in your own S3 bucket, so every computer you
  run ReGa on sees the same machines, and lists any leftover resources with
  a button to delete them.

## Not there yet

- Streaming. ReGa doesn't connect Moonlight to the machine or bring up the
  WireGuard tunnel yet, so you can't play from the app in this version.
- A full run on AWS. The Terraform has launched real (CPU) machines and the
  setup playbook runs on a real Windows Server in CI, but the app hasn't yet
  taken a machine from launch to stop on AWS, and nothing has run on a real
  GPU machine.
- x86_64 only, and not on Flathub yet.
